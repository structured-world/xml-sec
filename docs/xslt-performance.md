# XSLT Phase Measurements

```sh
cargo nextest run -p xml-sec-tools bench::xslt
cargo nextest run -p xml-sec-xslt --all-features --test phase_contract
cargo clean
LIBXSLT_SOURCE_DIR=/path/to/pinned/libxslt RUSTC_WRAPPER= \
  cargo run -p xml-sec-tools -- bench-xslt /tmp/xslt-measurement 100
```

Requires Rust 1.92+, CMake, a C compiler, pkg-config development files for
libxml2 and macOS/Linux `time`. `LIBXSLT_SOURCE_DIR` must match the committed
libxslt source pin; the runner builds that native oracle separately. On macOS
select non-Apple libxml2 consistently through `CMAKE_PREFIX_PATH` and
`PKG_CONFIG_PATH` (for example the same Homebrew libxml2 prefix), rather than
mixing headers/libraries or suppressing Apple's deprecated allocator API warning.
Existing output directories and evidence
inside the cleaned Cargo target directory are rejected. Actual native library
versions and CMake configuration are recorded. Test-only C never enters the product.

## Phase Boundaries

Both engines consume identical generated bytes and must match the complete
expected serialized bytes, including the final newline. Item-copy and binary
recursive amplification workloads run at two sizes. Unused named templates
scale compilation independently of source size. No transformation may do I/O.

| Phase | Included work |
| --- | --- |
| compile | Parse/compile stylesheet bytes; destroy temporary stylesheet |
| tree | Prepared stylesheet/source; execute, construct result, destroy execution state/result |
| serialize | Prepared result; serialize, destroy execution state/result |
| retained | Prepared stylesheet/source; execute, serialize, destroy execution state/result |
| end_to_end | Parse source, compile stylesheet, execute, serialize, destroy temporary objects |

Output equality assertions and serialized-buffer destruction follow the sample
timer in both engines. Execution-state/result destruction is inside it. File
reads, fixture preparation and three warmups are excluded. Serializer phases
retain preparation until they finish; percentile subtraction does not isolate
a phase. Opt-in hooks use production kernels and the same carried work/memory
meter. Hooks are absent without `benchmark-internals`. Rust retains deterministic
budgets; the reference denies I/O but has no corresponding Rust budget model.
This is not a claim of equal security enforcement or identical internal DOMs.

## Evidence And Memory

`results.json` preserves raw samples, nearest-rank p50/p95/p99, input/style/output
sizes and amplification across three process repetitions with alternating engine
order. One-sample CI runs check operability, not tail latency. Process peak RSS
includes preparation, warmups, live fixtures and reporting (macOS bytes; Linux
KiB converted to bytes). Raw system-time CPU/RSS reports accompany each record.
Never subtract setup RSS or call it isolated result-tree memory.
`output_amplification` is expected serialized output bytes divided by source XML
bytes; stylesheet size is reported separately. Compile/tree records carry this
fixture metadata, not a claim that those phases themselves serialize output.

`allocations.txt` is a separate Divan allocation run, not latency evidence. It
counts Rust allocations on the measured thread. `allocations-libxslt-*.json`
uses another executable with libxml/libxslt allocator hooks: successful allocation/
reallocation calls, requested bytes, peak live hook-owned bytes and extra peak
above prepared storage. It excludes libc/runner allocations and hook headers;
one measured operation follows warmups. These scopes differ from Divan and must
not be ranked as identical. Optional Linux `XSLT_BENCH_HEAP=1` adds full-process
Memcheck/Massif evidence; instrumented times never enter latency observations.

`result_tree_accounted_bytes` and `retained_stylesheet_bytes` describe Rust
storage accounting, not allocator peaks. Native result trees contribute to hook
live peak; no isolated heap figure is fabricated from RSS. Preserve exact source
fingerprints, revision/dirty state, dependency graph/lockfile, binary hashes,
host and toolchain. Successful runs clean binaries but retain raw evidence;
failures retain diagnostics.

## Reuse And Identity

There is no process-wide compilation lookup cache or output cache. Callers can
retain the immutable stylesheet; `retained` measures reuse, not a keyed lookup.
Internal module/document caches belong to their compilation/execution. Every
execution reauthorizes exact compiled dependency identities before source work.
Replacement revokes the old grant; recompilation obtains the new graph.
Concurrent executions share IR, not results, source, parameters or meters.

Contract tests cover phase equivalence, cumulative work/serialization limits,
concurrent success/refusal isolation and replacement-identity refusal. Existing
tests cover document-cache revocation/expiry and parse-provenance changes. A
future caller-owned compilation cache must bind exact stylesheet bytes, base
URI, dependency identities, engine version, compile semantics/budgets and policy
identity. No such cache or policy bypass is introduced or claimed here.

The required XSLT CI job publishes artifacts. Use controlled-host repetitions
before setting regression thresholds or making superiority claims. Hot-path
inspection uses `cargo flamegraph -p xml-sec-xslt --bench xslt --features benchmark-internals`;
profiling times do not substitute for uninstrumented latency samples.
