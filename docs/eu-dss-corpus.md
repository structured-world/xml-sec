# EU DSS XAdES corpus

Generated by `cargo run -p xml-sec-tools -- xades dss-corpus --record --results <directory>`, where the results directory must not exist yet; CI fails when a run differs from it.

Recorded with EU DSS 6.5.1, every XML input (`.xml` and `.xades`) of `dss-xades/src/test/resources` and `dss-cookbook/src/test/resources/signature-pool` at its release tag. Both validators get the same trust anchors (the topmost certificate of each signer chain the document carries) and the same time (1800000000 Unix seconds; a second pass, under each profile whose own run reached no validated path for any signature and found no timestamp token over a signature value that proves its existence, validates each signature at its own claimed signing time). The 57 other files of those directories carry neither extension (images, keystores, text, and XML that is no signature input such as an XSD schema): each is recorded as *not-xml*, meaning not an XML signature input, and validated by neither, and a change to that set fails the check.

Each profile's DSS run uses DSS's own default policy with every cryptographic constraint replaced by the profile's. An input *passes* when every signature reaches TOTAL_PASSED (ETSI EN 319 102-1 V1.4.1: DSS's simple report, and the shared EN 319 102-1 process over xml-sec's facts); it is in *agreement* when every signature reaches DSS's indication and sub-indication and every building block both validators reached says the same, with the same indication and sub-indication wherever xml-sec's facts conclude the block. Two classes come before that rule: *not-a-signature* when neither side reads a signature, and *no-usable-anchor* when the document carries no certificate a chain ends at, whatever the indications. *agreement*, *not-a-signature* and *no-usable-anchor* are automatic; every other input carries a reviewed class (normative-difference, policy-refusal, unsupported, dss-deviation) with its reason: the clause it rests on, or for a policy refusal the deployment rationale of the profile.

For every signature xml-sec passes, the expectations record until when it keeps passing (`valid_until`, Unix seconds): the first certificate validity bound past which the same process, over the evidence the document carries, no longer reaches TOTAL_PASSED. A signature that passes past every bound has none, and a pass where no signature has one lists no `valid_until`.
