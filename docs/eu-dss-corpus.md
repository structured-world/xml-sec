# EU DSS XAdES corpus

Generated by `cargo run -p xml-sec-tools -- xades dss-corpus --record`; CI fails when a run differs from it.

EU DSS 6.5.1, every XML input of `dss-xades/src/test/resources` and `dss-cookbook/src/test/resources/signature-pool` at its release tag. Both validators get the same trust anchors (where each chain the document carries ends) and the same time (1800000000 Unix seconds; a second pass at the claimed signing time when no signature reaches a validated path and the document carries no timestamp).

Each profile's DSS run uses DSS's own default policy with every cryptographic constraint replaced by the profile's. An input *passes* when every signature reaches TOTAL_PASSED (ETSI EN 319 102-1 V1.4.1: DSS's simple report, and the shared EN 319 102-1 process over xml-sec's facts); it is in *agreement* when every signature reaches DSS's indication and sub-indication. Each other input carries a reviewed class with the clause it rests on.

For every signature xml-sec passes, the expectations record until when it keeps passing (`valid_until`, Unix seconds): the last certificate validity bound past which the same process, over the evidence the document carries, still reaches TOTAL_PASSED.
